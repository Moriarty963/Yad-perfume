# YAD Club — запуск и безопасность

YAD Club — опциональный личный кабинет с входом по одноразовому коду из письма. Доступ к покупке без регистрации сохранён. На 6 ноября 2026 функция **не активирована**.

## Что сделано
- Отдельный маршрут `/account`, регистрация по имени и email, подтверждение шестизначным кодом, защищённая 30-дневная сессия.
- Профиль: имя, явно включаемая рекламная подписка, отключение рекламы, выход, удаление аккаунта.
- Отдельный журнал согласий (с датой и версией), подтверждённые подписчики учитываются в `/admin`.
- Ограничение запросов кодов, максимум 5 попыток кода, валидация входных данных, cookies `HttpOnly; Secure; SameSite=Lax`, проверка same-origin на изменяющие запросы.
- Никаких реальных писем/рекламы при выключенной функции; никаких регистраций и хранения новых пользовательских данных без настроенной инфраструктуры.

## До включения обязательно
1. Утвердить актуальную политику обработки персональных данных с настоящим оператором, контактами, сроками и целями. Сейчас `/club-privacy` — только проект документа.
2. Развернуть **отдельный PostgreSQL на территории России**, проверить соответствие 152-ФЗ (в том числе локализацию и трансграничные передачи). Выполнить `migrations/20261106_yad_club.sql` только на этой базе.
3. Подключить домен почтового отправителя и подтвердить DNS записи у Resend либо адаптировать отправку к юридически допустимому российскому провайдеру. Не использовать личные адреса/неподтверждённые домены.
4. Настроить в Vercel закрытые server-only environment variables:
   - `YAD_CLUB_DATABASE_URL` — строка подключения к базе на территории РФ;
   - `YAD_CLUB_SESSION_SECRET` — новый уникальный случайный секрет (не менее 32 символов);
   - `YAD_CLUB_FROM_EMAIL` — подтверждённый адрес отправителя, например `YAD Club <club@your-verified-domain>`;
   - `RESEND_API_KEY` — ключ с ограниченными правами только на отправку;
   - `YAD_CLUB_DATA_REGION=RU` — выставить после проверки местоположения и обработки;
   - `YAD_CLUB_PRIVACY_APPROVED=true` — выставить **после** публикации полноценной политики.
5. Проверить регистрацию на тестовом адресе с тестовым почтовым ящиком и только после этого переводить в production. Не включать автоматические рекламные рассылки до отдельной проверки согласий и юридического процесса.

Рекламная подписка **не обязательна** для регистрации. Рассылка не активируется до проверки кода из письма; отказ доступен в профиле. История заказов в `yad_orders` автоматически не связывается с новыми аккаунтами, чтобы не открывать чужие персональные данные. Почта для входа используется для транзакционных сообщений; отдельные рекламные рассылки потребуют самостоятельного настроенного инструмента и механизма отписки.

**Важное:** прежде чем переносить персональные данные клиентов в сторонний сервис email-рассылок, оцените основания для передачи и требуемые уведомления/разрешения по законам применимой страны.

## Проверки
- `GET /api/club` при незавершённой настройке возвращает `503 {enabled:false}`, не создаёт профиль.
- Прямая отправка рекламы не запускается автоматически, данные незарегистрированных посетителей не сохраняются новой функцией.
- SQL миграция проверена на отдельно выделенной тестовой ветке без создания пользователей.

## Подготовка кампаний
- В закрытой панели администратора появился **YAD / Студия акций**: заголовок, текст, ссылка, предпросмотр и копирование текста для Telegram-канала.
- Черновики хранятся **локально в браузере администратора** (до 12), не создают рассылок, не экспортируют и не отображают персональные данные покупателей. Для дальнейшего общего доступа между устройствами понадобится отдельное защищённое хранилище.
- Добавлен шаблон предложения о подарочном наборе YAD 3 × 20 мл за 4 900 ₽.

## Будущая рассылка и отписка
- Код `lib/yad-club-unsubscribe.js` создаёт и проверяет подписанные HMAC ссылки отписки сроком до 366 дней.
- `/unsubscribe` показывает подтверждение, `GET /api/club-unsubscribe` не изменяет подписку, `POST /api/club-unsubscribe` отключает её и фиксирует отказ в журнале согласий.
- Программа массовой отправки email **ещё не активирована**. При её подключении следует выпускать персональную подписанную ссылку для каждого письма, обеспечивать механизм отписки, не отправлять письма отказавшимся и отдельно проверить правомерность передачи данных провайдеру.
- Управление профилем и отписка продолжают работать при временной недоступности почтового отправителя, если база и требования допуска к данным настроены.
- Запрос одноразового кода ограничен на уровне БД; проверка количества попыток и регистрация согласий защищены транзакциями.

## Перед релизом
- Провести функциональный тест регистрации через настоящий подтверждённый домен отправителя и тестовый адрес (сейчас невозможен без подключения домена и отдельной БД РФ).
- Провести нагрузочную проверку ограничений отправки писем и проверить договор с процессором персональных данных.
- Убедиться, что шаблоны рекламных писем включают корректное указание отправителя, условия акции и рабочую отписку.
